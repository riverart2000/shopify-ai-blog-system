# Product Marketing Prompt Generator + Social Publisher

A two-script pipeline:

1. **`generate_prompts.py`** (script 1) — reads product URLs, fetches product +
   blog data, downloads source imagery, and writes **one JSON per product** with
   an ideal-client persona and, per creative concept, a detailed image prompt,
   the on-image text, and the social caption.
2. **`generate_social.py`** (script 2) — reads that JSON + images and, for each
   creative concept, **generates a marketing image** with Grok and writes a
   **ready-to-paste social post** text file next to it.

## Quick start

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Default: public web data + deterministic template prompts
python generate_prompts.py

# Shopify Admin API + Grok-authored prompts
python generate_prompts.py --fetcher shopify --generator grok

# One-off URL
python generate_prompts.py --url https://bioluxelab.com/products/some-product

# Step 2 — generate images + paste-ready social text (reads output/, writes social/)
python generate_social.py

# Higher-quality model + 2 variations, one concept only
python generate_social.py --quality --variations 2 --concept "Lifestyle Image"

# Step 3 — automatically publish a direct-response landing page to Shopify
python publish_landing_page.py --published

# Step 4 — Generate RSS feed for Publer ingestion
python generate_rss.py --base-url "https://your-server-domain.com/social/"
```

### AWS Lightsail / Linux Deployment

To automate this pipeline on an AWS Lightsail server:

1. **Upload your code** and set up the Python environment:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. **Configure your `.env` file** with the Shopify and Grok API keys.
3. **Set up Nginx** to serve the `social/` directory so Publer can fetch the RSS feed and images. Add a server block like this:
   ```nginx
   server {
       listen 80;
       server_name your-server-domain.com;
       
       location /social/ {
           alias /path/to/marketing/social/;
           autoindex on;
       }
   }
   ```
4. **Automate with Cron**:
   Edit your crontab (`crontab -e`) to run the provided wrapper script automatically (e.g. daily at 2am):
   ```bash
   0 2 * * * PUBLIC_BASE_URL="https://your-server-domain.com/social/" /path/to/marketing/run_pipeline.sh >> /path/to/marketing/pipeline.log 2>&1
   ```

### Landing Page Generation

Script 3 (`publish_landing_page.py`) automatically builds and publishes a high-quality Shopify landing page from the generated marketing assets:

1. It uploads the generated images to your Shopify store via the Admin GraphQL API (using the `stagedUploadsCreate` -> `fileCreate` flow).
2. It weaves the images and social copy into a "long-scroll" direct-response landing page structure (Hero → Agitate → Logic → Proof → CTA).
3. It creates the page via `pageCreate` and returns the live URL. The page inherits your theme's fonts and styling while applying custom layout CSS.

### Product fidelity (reference images required)

Marketing images are **only** generated by editing the **real product photos**
through Grok's image-**edit** endpoint, so the result keeps the actual product's
shape, colour and branding instead of reinventing it.

- `--max-references N` — number of real product images (1–3) used as
  reference. Default `3` (uses the main image plus additional angles when
  available).
- A product with **no** reference image on disk is **skipped entirely** — there
  is nothing to anchor the product to, so no image is produced.

Reference paths are read from the JSON `assets` (falling back to matching the
filename inside the input directory, so the `output/` folder can be moved).
Note the edit endpoint is billed for both the input and the output image.

The prompt also explicitly locks the product's **colour and finish** (e.g. keeps a
silver/metallic product from being rendered black) via a fidelity clause and
matching negative-prompt terms.

### Incremental / resumable runs

Because image generation is expensive, re-running `generate_social.py` only does
what is **missing**:

- If an **image** is missing, just that image is regenerated (and its text file).
- If only a **text file** is missing (the image is still there), it is recreated
  **without** calling the image API.
- Concepts whose image and text both exist are skipped.

Delete any output you want redone and re-run; everything else is left untouched.
Use `--overwrite` to force regeneration of everything.

Configuration is read from `.env` (see `Settings` in `product_prompts/config.py`).

## Inputs

| File                     | Purpose                                            |
|--------------------------|----------------------------------------------------|
| `product.list`           | One product URL per line.                           |
| `creative_concepts.list` | One creative concept per line (`Name – description`).|
| `.env`                   | API keys / Shopify + Grok credentials.              |

## Output

**Script 1** writes everything into a single `output/` directory:

```
output/
├── <product-handle>.json      # prompts + social copy + persona + campaign
├── <product-handle>_1.jpg     # main image
├── <product-handle>_2.jpg     # supporting images
└── <product-handle>_3.jpg
```

**Script 2** writes generated marketing images + paste-ready post text into
`social/` (one pair per creative concept):

```
social/
├── <product-handle>__<concept-slug>.jpg   # generated marketing image
└── <product-handle>__<concept-slug>.txt   # paste-ready post: title, caption, offer, keywords, hashtags
```

With `--variations N > 1`, files get a `_v1`, `_v2`, … suffix.

The `.txt` file contains **only** the text you copy straight into a social
platform — the title, caption/description, the offer, the **product link**,
long-tail keywords and hashtags, in that order, with no labels or metadata. When
a discount code is configured it is appended to the product URL
(`…?discount=CODE`) so it auto-applies at checkout. The offer line is omitted
automatically when the caption already mentions it, and hashtags are de-duplicated.

`product.json` schema (abridged):

```jsonc
{
  "schema_version": 1,
  "generator": "template",
  "product":  { "handle", "title", "vendor", "description_text", ... },
  "blog":     { "url", "title", "text", "image_urls" },
  "main_image": "output/<handle>/images/image_00.jpg",
  "assets":   [ { "source_url", "local_path", "role" } ],
  "creative_concepts": [
    {
      "concept": "Lifestyle Image",
      "image_prompt": "…detailed text-to-image prompt…",
      "social_text": "…caption + hashtags…",
      "negative_prompt": "…",
      "aspect_ratio": "1:1",
      "hashtags": ["#…"],
      "keywords": ["long-tail search phrase", "…"]
    }
  ]
}
```

## Architecture

```
product_prompts/
├── config.py            # Settings from .env
├── models.py            # typed dataclasses
├── concepts.py          # parse creative_concepts.list
├── utils.py             # logging, HTTP session (retries), html->text, slugify
├── fetchers/            # PLUGGABLE product sources
│   ├── base.py          #   ProductFetcher ABC
│   ├── web.py           #   public /products/<handle>.json (+ HTML fallback)
│   └── shopify.py       #   Shopify Admin GraphQL API
├── blog.py              # find blog URL in description + scrape it
├── images.py            # download images
├── prompting/           # PLUGGABLE prompt engines
│   ├── base.py          #   PromptGenerator ABC
│   ├── template.py      #   deterministic, offline (default)
│   └── grok.py          #   xAI/Grok chat API (auto-falls back to template)
└── pipeline.py          # orchestration
generate_prompts.py      # CLI entry point (script 1)

social_publisher/        # SCRIPT 2 — image generation + social text
├── loader.py            # read output/*.json
├── caption.py           # compose paste-ready post text file
├── image_backends/      # PLUGGABLE image models
│   ├── base.py          #   ImageBackend ABC
│   └── grok.py          #   Grok /images/generations (grok-imagine-image)
└── pipeline.py          # orchestration
generate_social.py       # CLI entry point (script 2)
```

### Extending

- **New data source** → add `fetchers/<name>.py` implementing `ProductFetcher`,
  register it in `fetchers/__init__.get_fetcher`.
- **New prompt engine** → add `prompting/<name>.py` implementing
  `PromptGenerator`, register it in `prompting/__init__.get_generator`.
- **New image model** → add `image_backends/<name>.py` implementing
  `ImageBackend`, register it in `image_backends/__init__.get_image_backend`.
- **New creative concept** → add a line to `creative_concepts.list`. The template
  engine has bespoke builders for known concepts and a strong generic fallback
  for anything new.

## Design notes

- **Robust by default:** the `web` fetcher needs no credentials and works on any
  Shopify storefront via the public `.json` endpoint, with an HTML/JSON-LD
  fallback.
- **Never hard-fails on the LLM:** the Grok backend gracefully falls back to the
  deterministic template generator on any error (missing key, rate limit, etc.).
- **Batch-safe:** one failing URL is logged and skipped; the rest still process.
